# REGISTRY + GOVERNANCE

## Central law

No major capability should exist only by implication. Important engines, workflows, features, roles, routes, schemas and configurations should be explicitly registered.

## Registry types

REQUEST, PROMPT, ENTITY, SCHEMA, FIELD, RELATIONSHIP, COMPONENT, MODULE, FEATURE, RULE, WORKFLOW, PERMISSION, ROLE, WORKSPACE, API, WEBHOOK, CONNECTOR, EVENT, DECISION, DOCTRINE, CONTEXT, REASONING, NAME, ARTIFACT, QA.

## Governance

Proposed → reviewed → approved → active → deprecated.

## Architecture verifier

Detect duplicates, responsibility leakage, naming collisions, orphaned routes, missing permissions, stale documentation and unregistered production configuration.
